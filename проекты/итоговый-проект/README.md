# Итоговый проект. Система мониторинга подписки

**Вес:** 30% итоговой оценки · **Блокирующий элемент** · **Формат:** группа 2–3 человека
**Выдача:** лекция темы 07 (07.11) · **Сдача:** 07.12, 23:59 · **Защита:** семинар темы 12 (09/12.12)

---

## Задача

Собрать работающую систему, которая сама ходит за данными, считает метрики ПРАЙМ, замечает аномалии и сообщает о них — по расписанию, без вашего участия.

Это не новый проект с нуля: он складывается из того, что вы делали на семинарах тем 07–11. Если вы делали семинары, к защите останется собрать и отполировать.

## Что должно быть в репозитории

1. **Пакет** с разделением слоёв: загрузка, преобразование, расчёт метрик, доставка.
2. **Конфигурация и журналирование.** Секретов в коде нет.
3. **Загрузка** из учебной базы и минимум одного внешнего API.
4. **Витрина метрик** — не менее пяти метрик, среди них хотя бы одна с факторной декомпозицией.
5. **Проверки качества данных** и правила алертов.
6. **Доставка**: бот присылает отчёт с графиками и алерты.
7. **Дашборд** (Streamlit) или выгрузка в Google Sheets.
8. **Запуск по расписанию.**
9. **README**: как развернуть, как запустить, какие метрики и почему они выбраны.
10. **Декларация ИИ.**

## Защита

12–15 минут на команду: 5 минут демонстрации вживую, 5 минут вопросов, 3 минуты разбора.

**Вопросы задаются каждому участнику по его части решения.** Участник, который не может объяснить и воспроизвести собственный вклад, получает индивидуально сниженную оценку — независимо от того, насколько хорош проект в целом.

Распределите работу так, чтобы каждый отвечал за понятный кусок и знал его целиком. «Я делал дашборд, а как работает загрузка — не смотрел» — это минус баллы.

## Критерии — 30 баллов

| Критерий | Баллов |
|---|---|
| Решение разворачивается и запускается с нуля по README | 4 |
| Архитектура пакета и разделение слоёв | 4 |
| Загрузка из базы и API устойчива и инкрементальна | 4 |
| Метрики корректны, выбор обоснован | 5 |
| Проверки и алерты осмысленны, не шумят | 4 |
| Доставка работает **вживую на защите** | 3 |
| README и декларация ИИ | 2 |
| Защита: каждый участник объясняет свою часть | 4 |

## Что означает «блокирующий»

Оценка ниже 4 баллов по 10-балльной шкале за итоговый проект ограничивает итоговую оценку по дисциплине. При неудовлетворительном результате проект дорабатывается с учётом замечаний и защищается повторно в установленный срок.

## Частые способы потерять баллы

- Всё работает на ноутбуке автора и больше нигде. Проверьте на чужой машине по своему же README.
- Пароль от базы в коде или в истории коммитов.
- Бот, который присылает алерт каждый час: это не мониторинг, а шум. Обоснуйте пороги.
- Повторный запуск дублирует данные.
- На защите не запускается «потому что интернет» — проверьте заранее и держите запасной вариант.

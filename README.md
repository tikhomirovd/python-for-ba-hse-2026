## О чём курс

Это не курс «изучаем pandas». Это курс о том, как аналитик доводит задачу до конца: получает данные, считает метрику, объясняет её бизнесу — и превращает разовый расчёт в решение, которое работает само.

Весь семестр вы собираете **один продукт** — систему мониторинга экосистемной подписки. Каждый семинар добавляет к ней работающий компонент: подключение к базе, витрину данных, расчёт метрик, анализ пилота, проверки качества, загрузку из внешних API, бота с алертами, дашборд, запуск по расписанию. К декабрю у вас есть не набор ноутбуков, а работающая система, которую не стыдно показать на собеседовании.

Статистику и методы исследования читает НИС «Методы анализа данных», проектирование баз данных и SQL — «SQL и базы данных». Здесь этого нет: мы занимаемся тем, что происходит между ними.

## Оценивание

```
Онакопленная = 0,10·Посещаемость + 0,15·Проверочные работы
             + 0,25·Практические задания + 0,20·Проект 1     (максимум 7 из 10)

Оитоговая    = Онакопленная + 0,30·Экзамен
```

| Элемент | Вес | Формат |
|---|---|---|
| Посещаемость | 10 % | Все 24 аудиторных занятия |
| Проверочные работы | 15 % | 4 работы по 10 мин на лекциях (по 2,5 %) + итоговый тест 30 мин (5 %) |
| Практические задания *(далее — ДЗ)* | 25 % | 4 задания по 6,25 %, у каждого свои параметры |
| [Проект 1](проекты/) | 20 % | Индивидуально. Аналитическая записка + устная защита |
| [Экзамен](проекты/) | 30 % | Защита итогового проекта, группа 2–3. **Блокирующий** |

**Экзамен — блокирующий элемент.** Оценка ниже 4 баллов за экзамен ограничивает итоговую оценку по дисциплине неудовлетворительной независимо от накопленной. Элементы текущего контроля пересдаче не подлежат.

## Правила курса

**Проверочные работы и итоговый тест** пишутся без компьютера, без интернета и без ИИ-ассистентов. Они проводятся на лекциях, одновременно для обеих групп.

**Домашние задания и проекты** можно делать с ИИ-ассистентами — это часть профессиональных навыков, и мы отдельно разбираем, как ими пользоваться (тема 12). Но:

- к каждой сдаче прикладывается **декларация**: какой инструмент, для чего, какие существенные подсказки давали;
- на защите вам будут задавать вопросы **по вашему коду**: почему здесь именно такое соединение, что сломается, если убрать вот эту строку;
- **неспособность объяснить собственную работу приравнивается к её невыполнению** независимо от того, насколько хорошо она сделана.

Это не про недоверие. Инструмент, которым вы не можете проверить результат, делает вас слабее, а не сильнее — и на работе это выяснится дороже, чем здесь.

**Каждое задание выполняется с индивидуальными параметрами** — закреплённый за вами сегмент, сервис, период или пилот. Совпадение решений трактуется как нарушение академических норм.

**Учётные данные** доступа к учебному серверу нельзя передавать третьим лицам и отправлять в сторонние сервисы, включая ИИ-ассистентов.

## Как начать

Понадобятся Python 3.12+, [uv](https://docs.astral.sh/uv/), Git и аккаунт на GitHub. Python отдельно ставить не нужно — его поставит uv, и уже установленные у вас версии он не тронет.

**[Что должно быть готово к первому семинару](справка/к-семинару.md)** — чек-лист и проверка окружения.
Пошаговые инструкции: **[Windows](справка/установка-windows.md)** · **[macOS](справка/установка-macos.md)**.

Дальше, когда окружение готово:

```bash
git clone <адрес этого репозитория>
cd python-for-business-analytics
uv sync
cp .env.example .env      # и вписать в него строку из бота, команда /db
uv run jupyter lab
```

Доступ к учебной базе выдаёт бот курса по команде `/db`. Пароль хранится в файле `.env`, который закрыт в `.gitignore` и **никогда** не коммитится. Что делать, если не подключается, — в памятке **[«Подключение к учебной базе»](справка/подключение-к-базе.md)**.

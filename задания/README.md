## Как сдавать

Все задания делаются в **вашем репозитории `prime-monitor`**. Вы завели его из [шаблона](https://github.com/tikhomirovd/prime-monitor-template), и он живёт весь семестр: каждое задание добавляет в него следующий кусок системы мониторинга.

1. Работа идёт в отдельной ветке и оформляется **pull request** в `main` вашего репозитория.
2. Сдача — командой `/submit` в [боте курса](https://t.me/hse_python_2627_bot): **ссылка на pull request**, вида `https://github.com/ВАШ_ЛОГИН_НА_GITHUB/prime-monitor/pull/N`, где `N` — номер pull request. Файлы и скриншоты бот не принимает.
3. Pull request остаётся **открытым**: я смотрю его и оставляю комментарии прямо в нём. Когда в боте появилась оценка — сливаете сами (**Merge pull request**) и делаете `git pull` в `main`.
4. Репозиторий может быть публичным или приватным. Если приватный — добавьте `tikhomirovd` в Settings → Collaborators, иначе ссылка отдаёт 404 и работа считается несданной.
5. В репозитории лежит заполненная декларация ИИ — своя на каждую работу. У ДЗ-1 это `ДЕКЛАРАЦИЯ-ИИ.md` из шаблона; у следующих работ — копия этого файла с названием работы: `ДЕКЛАРАЦИЯ-ИИ-ДЗ-2.md`, `ДЕКЛАРАЦИЯ-ИИ-ПРОЕКТ-1.md`. Отдельный файл нужен, чтобы pull request разных работ не конфликтовали между собой.

Прислать новую версию можно, пока открыт приём: новый `git push` в ветку и **снова** `/submit`. Проверяется версия на момент последней отправки; push без повторной отправки не учитывается. Но если первая сдача была в срок, а новая пришла после дедлайна, штраф за просрочку посчитается по новой — бот предупредит перед тем, как принять.

## Как оценивается

У каждого задания своя разбалловка с понятными проверками — она стоит в тексте задания вместе с формулой перевода в 10-балльную оценку. Разбалловка разложена по четырём критериям программы дисциплины:

| Критерий | Доля |
|---|---|
| Корректность результата и отсутствие методических ошибок | 40 % |
| Обоснованность принятых решений и качество кода | 30 % |
| Воспроизводимость запуска у преподавателя | 20 % |
| Оформление результата и декларация использования ИИ | 10 % |

**Параметры у каждого свои** — закреплённый за вами участок данных. Совпадение решений трактуется как нарушение академических норм.

**Код и ответы словами оцениваются по-разному.** Код можно писать вместе с ИИ-ассистентом — это часть профессиональных навыков, декларация обязательна. А выводы и ответы на вопросы по данным пишете сами: **текст, написанный LLM, получает 0 баллов.**

**Преподаватель вправе задать вопросы по сданной работе.** Неспособность объяснить собственное решение обнуляет оценку за задание. Вопросы будут не по теории, а по вашему коду и вашим выводам: почему здесь так и что сломается, если убрать эту строку.

## Просрочка

За каждые начатые сутки после дедлайна из оценки за работу вычитается 1 балл из 10, но штраф не опускает оценку ниже 4 баллов при сдаче в течение недели после дедлайна (работа, оценённая ниже 4, сохраняет свой балл); позже — 0 баллов. Пример: работа на 9 баллов, сданная на двое суток позже, получает 7; работа на 6 баллов с тремя сутками просрочки — 4. Сдать через минуту после дедлайна — это уже сутки просрочки и минус 1 балл.

Бот принимает работу и после дедлайна и сразу показывает, сколько баллов снимется.

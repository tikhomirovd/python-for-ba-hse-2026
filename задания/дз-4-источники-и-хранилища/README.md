# ДЗ-4. Утренняя выручка ПРАЙМ

| Выдача | Дедлайн для обеих групп | Приём со снижением балла | Вес |
|---|---|---|---|
| 28 ноября 2026 | **5 декабря, суббота, 23:59 МСК** | до 12 декабря, 23:59 МСК | 6,25 % итоговой оценки |

ПРАЙМ получает платежи за подписки в рублях, а с зарубежным партнёром рассчитывается в другой валюте. Каждое утро финансовой команде нужны обе суммы. Даже если Банк России не ответил, команда должна увидеть вчерашнюю выручку в рублях.

Добавьте в свой `prime-monitor` две команды. Одна собирает отчёт за неделю по платежам и курсам ЦБ. Вторая сравнивает PostgreSQL и ClickHouse, чтобы вы могли посоветовать команде базу для отчёта. **Как назвать команды, устроить пакет и оформить отчёт, решаете вы.** Своя реализация может получить полный балл. Ориентир — 5–8 часов.

## 1. Узнайте свой вариант

Создайте ветку `feature/hw4` от `main`, даже если ДЗ-3 ещё на проверке. Запрос в учебной PostgreSQL под вашим логином покажет номер варианта, даты и валюту.

```sql
SELECT variant,
       DATE '2025-04-07' + (variant::int - 1) AS first_day,
       DATE '2025-04-07' + (variant::int + 5) AS last_day,
       (ARRAY['USD', 'CNY', 'JPY'])[(variant::int - 1) % 3 + 1] AS currency
FROM prime.hw3_variants
WHERE login = current_user;
```

Номер тот же, что в ДЗ-3. У варианта 1 неделя начинается 7 апреля 2025 года. Каждый следующий номер сдвигает начало на день, валюты USD, CNY и JPY чередуются. У варианта 3 получится **9–15 апреля, JPY**. Передавайте номер параметром — при проверке я запущу другую неделю. Если запрос не помог узнать номер, напишите мне.

## 2. Посчитайте выручку в PostgreSQL и ClickHouse

В обеих базах вы можете читать таблицу `prime.payments`. Отправьте `/db` в личный чат с [ботом курса](https://t.me/hse_python_2627_bot). Скопируйте строку `PRIME_DSN` для PostgreSQL и блок переменных `CH_…` для ClickHouse в локальный `.env` вашего проекта. У баз разные пароли. В `.env.example` перечислите имена настроек, а поля для паролей оставьте пустыми. Проверьте, что в Git и логах секретов нет. [Подключение к PostgreSQL](../../справка/подключение-к-базе.md) · [Драйвер ClickHouse для Python](https://clickhouse.com/docs/integrations/language-clients/python/driver-api)

Драйвер PostgreSQL уже в шаблоне. При необходимости выполните `uv add requests clickhouse-connect`. В `clickhouse_connect.get_client(...)` передайте порт из `CH_PORT` как число и включите TLS параметром `secure=True`. Оба подключения из Python можно проверить запросом `SELECT paid_at, status, amount FROM prime.payments LIMIT 1`.

Посчитайте показатели на каждом сервере **по UTC**. Границы передайте параметрами SQL. Для недели 9–15 апреля условие по времени — от полуночи 9-го включительно до полуночи 16-го исключительно.

| Что положить в отчёт | Как посчитать |
|---|---|
| День (`day`) | Дата платежа `paid_at` по UTC |
| Попытки оплаты (`attempts`) | Все строки за день |
| Успешные платежи (`successful`) | Строки, где `status = 'success'` |
| Выручка в копейках (`revenue_kopecks`) | Сумма `amount` в рублях по успешным платежам, умноженная на 100 |

В отчёте семь строк по порядку. За день без платежей поставьте нули. Сверьте три показателя по каждой дате. При расхождении программа должна показать дату и остановить сравнение.

**При сбое сервера** запишите время и ошибку без пароля. Для отладки подойдёт региональный снимок с С10 (`data/s9_s10/payments.csv`) в SQLite и DuckDB. Для сдачи нужны замеры **PostgreSQL и ClickHouse**. Если сбой затянулся, напишите мне до дедлайна. [Скачать тот же снимок платежей](https://raw.githubusercontent.com/tikhomirovd/prime-l9-workshop/step-6/data/payments.csv)

## 3. Добавьте курс ЦБ. Что произойдёт, если он не загрузится?

Сделайте запрос к `https://www.cbr.ru/scripts/XML_daily.asp` с параметром `date_req` в формате `ДД/ММ/ГГГГ`. Найдите свою валюту по `CharCode`. Поле `VunitRate` показывает, сколько рублей стоит **одна** единица валюты. То же число можно получить из `Value / Nominal`. В XML дробная часть отделена запятой. [Описание API Банка России](https://www.cbr.ru/development/SXML/)

В воскресенье может действовать субботний курс. Сохраните в локальной базе **обе даты** — день запроса и дату курса из атрибута `Date`. Ключ записи — день запроса и валюта. Перед загрузкой проверьте, какие дни уже есть. Не хватает среды? Запросите только среду.

К каждому дню отчёта добавьте валюту, дату курса, рубли за единицу и выручку в валюте (`revenue_kopecks / 100 / курс`, до двух знаков). Если курс недоступен, оставьте валютную сумму пустой, отметьте причину и покажите рублёвые показатели.

Задайте тайм-аут. Если сервер не успел ответить, связь оборвалась, пришёл 429 или 5xx, пауза и повтор могут помочь. На дату — **до трёх попыток, включая первую**. При 403 сервер отказал в доступе, поэтому достаточно одного запроса. Запишите день и причину сбоя в журнал. Сохраните курс, когда получите корректный ответ.

Выберите день своей недели и проверьте четыре ситуации. Подойдут тесты, вывод программы или журнал с датами и числом запросов.

| Что сделать | Что должно произойти |
|---|---|
| Начните с пустой базы курсов. За выбранный день подставьте ответ 503 | После повторов останется один пропуск курса. В отчёте видна выручка за все семь дней. |
| Верните обычный ответ ЦБ и запустите отчёт с той же базой | Программа запросит только пропущенный день. Появится валютная сумма. |
| Запустите отчёт ещё раз | Запросов к ЦБ — ноль. Отчёт и число сохранённых записей прежние. |
| На новой тестовой базе подставьте 403 за выбранный день | За этот день будет один запрос. Выручка в рублях останется в отчёте. |

<details>
<summary>Как подставить 503, когда сайт ЦБ работает?</summary>

Для `requests` подойдёт библиотека `requests-mock` (`uv add --dev requests-mock`). Этот пример вернёт 503 только за 13 апреля.

```python
import requests
import requests_mock

url = "https://www.cbr.ru/scripts/XML_daily.asp"
day = "13/04/2025"

with requests_mock.Mocker(real_http=True) as api:
    failed = api.get(f"{url}?date_req={day}", status_code=503)
    response = requests.get(url, params={"date_req": day}, timeout=5)
    print(response.status_code, failed.call_count)  # 503, одна попытка
```

Подставьте свою дату. Если внутри блока вызвать функцию отчёта, `failed.call_count` покажет число её попыток за день. После выхода из блока снова отвечает ЦБ. [Примеры requests-mock](https://requests-mock.readthedocs.io/en/latest/mocker.html)

</details>

## 4. Сравните PostgreSQL и ClickHouse

Для каждой базы запустите **отдельный процесс Python**, иначе первый драйвер повлияет на пик памяти второго. Откройте соединение, прогрейте его одним запросом и сделайте минимум три повтора за ту же неделю. Засекайте время от отправки SQL до получения всех строк в Python.

| Хранилище | Время каждого повтора, мс | Медиана, мс | Пик памяти клиента, МиБ |
|---|---|---:|---:|
| PostgreSQL | | | |
| ClickHouse | | | |

Под таблицей укажите период, где запускали Python и где находились базы. Максимальный RSS — пик памяти процесса Python вместе с драйвером. Потребление памяти сервером по нему определить нельзя. После замеров в каждом процессе вызовите функцию с С10. На Windows для неё понадобится `uv add psutil`.

```python
import sys


def peak_mib() -> float:
    """Пик резидентной памяти текущего процесса за всё время его работы, МиБ."""
    if sys.platform == "win32":
        import psutil

        return psutil.Process().memory_info().peak_wset / 2**20

    import resource

    peak = resource.getrusage(resource.RUSAGE_SELF).ru_maxrss
    return peak / (2**20 if sys.platform == "darwin" else 2**10)
```

# ДЗ-2. Витрина клиента

| Выдача | Дедлайн | Приём со снижением балла | Вес |
|---|---|---|---|
| 26.09 | **04.10, воскресенье, 23:59** | до 11.10 | 6,25 % итоговой оценки |

Вы — аналитик ПРАЙМ, и у вас свой **сегмент клиентов**. Бот прислал его 26 сентября готовым условием для `where`; оно же лежит в вашей строке `prime.assignments`, в колонке `client_filter`. Сегменты у всех разные, поэтому и числа, и выводы у каждого свои.

Задача недели — собрать **витрину клиента**: таблицу, в которой одна строка — один клиент, а рядом всё, что мы про него знаем. Это ровно то, что мы делали на семинаре С4, только теперь на вашем сегменте и с задачами поверх витрины. Задачи идут лесенкой: сначала вы дописываете один аргумент, как на семинаре, потом целую строку, потом пишете задачу сами, а в конце собираете витрину и доказываете протоколом сборки, что двойного счёта нет.

> **Главное правило.** Код можно писать вместе с ИИ-ассистентом — это нормально, только отметьте это в `ДЕКЛАРАЦИЯ-ИИ-ДЗ-2.md`. **Ответы словами пишите сами: текст, написанный LLM, получает 0 баллов.** Здесь оценивается, как думаете вы. Если ответ вызовет сомнение, я попрошу пояснить его устно.

## Шаг за шагом

### 1. Ветка ДЗ-2 растёт из `main`, а не из ветки ДЗ-1

Pull request ДЗ-1 остаётся открытым до оценки — это нормально. ДЗ-2 делается в **отдельной ветке от `main`**: в `main` нет вашей работы по ДЗ-1, и ветки друг другу не мешают — они трогают разные файлы. Когда придёт оценка за ДЗ-1 и вы его сольёте, pull request ДЗ-2 это не заденет.

Окружение и доступ к базе — те же, что в ДЗ-1. Если `.env` уже работает, ничего делать не нужно.

## Как оценивается

**Основная часть — до 8 баллов. 9 и 10 — только за исследование.** Сделали всё аккуратно — это 8, и это «отлично».

### Основная часть: 20 баллов, оценка = сумма × 0,4

| Блок | Что проверяется | Баллы |
|---|---|---|
| **Уровень 1** | 4 задачи по 0,25 | 1 |
| **Уровень 2** | 4 задачи по 0,75 | 3 |
| **Уровень 3** | 4 задачи по 1 | 4 |
| **Витрина и протокол сборки** (задача 13) | одна строка — один клиент, все колонки из условия | 1,5 |
| | каждое соединение записано через `step()`, кратность и ожидаемые потери объявлены до сборки | 2,5 |
| | строки ЗЕРНО, ДЕНЬГИ и ЛЮДИ сходятся: `ok` | 2,5 |
| | протокол печатается прогоном ноутбука и сходится и на контрольном сегменте | 1 |
| **Проверка из `checks.py`** | функция из вашего `src/prime/checks.py` применена к витрине и стоит строкой протокола с ожиданием | 1,25 |
| **Ответы словами** | 4 ответа по 0,5: числа верные — 0,25, вывод из них верный и объяснён — ещё 0,25 | 2 |
| **Сдача** | открытый pull request `feature/hw2` → `main`; в git нет `.env` и выгрузок, ноутбук без выводов; `ДЕКЛАРАЦИЯ-ИИ-ДЗ-2.md` заполнена | 0,75 |
| | ноутбук выполняется целиком без правок — на вашем сегменте и на контрольном | 0,5 |

**Протокол сборки — это 3 балла из 10**, как и было сказано на лекции: 7,5 из 20. **Без протокола этот блок — ноль, даже если числа верные.** Проверка из `checks.py` — ещё 0,5 из 10, как обещано на семинаре С3.

**Задачи 1–12.** Полный балл — ответ верный и на вашем сегменте, и на контрольном. Верно по сути, но формат не тот — половина. Верно только на вашем сегменте — 0, и по коду этой задачи будет устный вопрос.

**Контрольный сегмент.** При проверке я запускаю ваш ноутбук ещё раз, подставив в ячейку 1.2 условие другого сегмента. Если код честно считает от загруженных таблиц, ответы пересчитаются сами. Если ответ вписан руками или код завязан на ваши числа — не пересчитаются.

**Ответ словами на 0,5 балла** — это 2–4 предложения с вашими числами и вашим выводом. Пример формы, не содержания — ситуация и числа выдуманы: «В кофейне 4 % чеков оформлены как возврат, на 18 300 ₽. Прибавлять их к выручке нельзя — этих денег у кофейни нет; вычитать тоже нельзя — в выручку они и так не вошли, и мы вычли бы их второй раз».

### Исследование: до +2 балла

Часть 7 ноутбука — исследование «Подорожание 1 марта» в двух частях, каждая до 1 балла сверху. **Засчитывается, если основная часть набрала не меньше 15 баллов из 20.**

| Каждая часть | Балл |
|---|---|
| числа верные и получены кодом в ноутбуке, а не вписаны руками | 0,4 |
| вывод следует из чисел, названо, чего расчёт не доказывает | 0,3 |
| код выполняется у меня целиком, в том числе на контрольном сегменте. Ошибка в коде исследования снимает только эти 0,2 | 0,2 |
| изложено по схеме: вопрос → как проверяли → что получилось → что это значит | 0,1 |

**Итоговая оценка = сумма основной части × 0,4 + баллы за исследование**, не больше 10.

### Как это ложится на критерии программы

Это раскладка той же суммы по критериям программы дисциплины, а не отдельные правила начисления.

| Критерий программы | Основная часть, из 20 | Исследование, из 1 за каждую часть |
|---|---|---|
| корректность результата и отсутствие методических ошибок | 8: задачи 1–12 | 0,4 |
| обоснованность решений и качество кода | 6: витрина одного зерна — 1,5, шаги протокола с ожиданиями — 2,5, ответы словами — 2 | 0,3 |
| воспроизводимость запуска у преподавателя | 4: ЗЕРНО, ДЕНЬГИ и ЛЮДИ сходятся — 2,5, протокол сходится на контрольном сегменте — 1, прогон без ошибок — 0,5 | 0,2 |
| оформление результата и декларация ИИ | 2: строка проверки в протоколе — 1,25, pull request и декларация — 0,75 | 0,1 |

**Неспособность объяснить собственный код или ответ обнуляет оценку за задание.** Вопросы будут по вашей работе: почему здесь `left`, что станет с протоколом, если убрать этот `groupby`. Правила просрочки — общие для всех заданий, [здесь](../README.md#просрочка).

## Если что-то не работает

| Что видите | Что случилось и что делать |
|---|---|
| `NameError: name 'ЗАПОЛНИТЕ' is not defined` | так и задумано: впишите вместо `ЗАПОЛНИТЕ` свой код. Не получается — замените всё содержимое ячейки строкой `answer_N = None` |
| `NameError` с другим именем | какая-то ячейка выше не выполнилась. Найдите сверху первую ячейку с красной ошибкой, исправьте её и сделайте **Restart Kernel and Run All Cells** |
| `MergeError: Merge keys are not unique…` | `validate=` поймал кратность, которую вы не объявили. Это не поломка, а подсказка: у ключа с одной из сторон несколько строк — сверните её до зерна перед соединением |
| `TypeError: Invalid comparison between dtype=datetime64[…, UTC] and …` | сравниваете момент с часовым поясом и дату без него. Даты справочника переводите в UTC: `.dt.tz_localize("UTC")`, как в задаче 6 |
| `ModuleNotFoundError: No module named 'prime.checks'` | нет файла `src/prime/checks.py` — см. шаг 3 |
| `Пакет prime не найден` | ноутбук запущен не в окружении `prime-monitor`: закройте JupyterLab, перейдите в корень `prime-monitor`, `uv run jupyter lab` |
| `Не найдена переменная PRIME_DSN` | нет `.env` в корне `prime-monitor` — [памятка](../../справка/подключение-к-базе.md) |
| подключение висит, `timed out` | сеть режет порт 5432 — замените в `.env` `:5432` на `:443` |
| выгрузка в ячейке 1.3 идёт дольше двух минут и падает с `canceling statement due to statement timeout` | сервер перегружен — повторите позже. Не проходит второй раз — напишите в чат курса |
| `IndexError: single positional indexer is out-of-bounds` в ячейке 1.2 | в `.env` не ваш логин: строки сегмента для этого пользователя нет. Возьмите строку подключения заново командой `/db` |
| `❌ нужен …, сейчас …` в итоге | ответ записан не в том формате. `numpy`-число превратите в обычное: `int(...)`, `round(float(...), 2)` |
| `a branch named 'feature/hw2' already exists` | ветка уже есть — `git switch feature/hw2` |
| отправили ссылку вида `…/pull/new/feature/hw2` | это ещё не pull request: откройте её, нажмите **Create pull request** и отправьте в `/submit` адрес открывшейся страницы |
| `Kernel is running over TCP without encryption` | безвредно, не обращайте внимания |

Ошибки git и подключения, которых здесь нет, — в разделе «Если что-то не работает» [ДЗ-1](../дз-1-окружение-и-репозиторий/README.md#если-что-то-не-работает).

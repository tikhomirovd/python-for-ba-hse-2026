## Шаг за шагом

### 1. Репозиторий

Нужен ваш репозиторий `prime-monitor`, созданный из [шаблона](https://github.com/tikhomirovd/prime-monitor-template) кнопкой **Use this template** (не Fork). Если его ещё нет — [Git-практикум](../../02-среда-git-python/семинар/С2-git-практикум.md), разделы 1–3, это десять минут.

Приватный он или публичный — неважно. Важно, чтобы ссылка открывалась у меня: если репозиторий **приватный**, добавьте `tikhomirovd` в **Settings → Collaborators**. Приглашение принимаю я; если оно висит в статусе Pending дольше двух дней — напишите. Непринятое приглашение через семь дней сгорает — тогда пригласите заново.

### 2. Окружение

В терминале, в папке `prime-monitor`:

```
git switch main
git pull
uv sync
uv run nbstripout --install
git config --global core.quotepath false
git config --global pull.rebase false
```

- `uv sync` ставит ровно те версии библиотек, что записаны в `uv.lock`.
- `nbstripout` при каждом коммите срезает из ноутбука выводы ячеек: в репозиторий уходит чистый код и ваш текст, а на экране всё остаётся как было. Если перенесёте папку проекта в другое место, `git add` ноутбука начнёт падать с `clean filter 'nbstripout' failed` — повторите `uv run nbstripout --install`.
- `core.quotepath false` — чтобы git показывал русские имена файлов (`ДЕКЛАРАЦИЯ-ИИ.md`) буквами, а не кодами.
- `pull.rebase false` — чтобы `git pull` сливал изменения, а не падал, если вы что-то правили и в браузере на GitHub, и у себя.

### 3. Доступ к базе

Нужен файл `.env` в корне `prime-monitor` со строкой `PRIME_DSN=...` — её выдаёт бот по команде `/db`. Как это делается и что делать, если не подключается, — в [памятке по подключению](../../справка/подключение-к-базе.md). Коротко: не подключается — замените в `.env` порт `5432` на `443`.

### 4. Стартовый ноутбук — в `main`

1. Откройте [hw1.ipynb](hw1.ipynb) на GitHub и нажмите кнопку **Download raw file** (стрелка вниз справа над файлом).
2. Сохраните файл в папку `notebooks` своего `prime-monitor` под именем `hw1.ipynb`. **Пока не открывайте и не запускайте.** Если с браузером не выходит — из корня `prime-monitor` одной командой, одинаково на macOS и Windows (в PowerShell — именно `curl.exe`):

   ```
   curl.exe -L -o notebooks/hw1.ipynb "https://raw.githubusercontent.com/tikhomirovd/python-for-ba-hse-2026/master/%D0%B7%D0%B0%D0%B4%D0%B0%D0%BD%D0%B8%D1%8F/%D0%B4%D0%B7-1-%D0%BE%D0%BA%D1%80%D1%83%D0%B6%D0%B5%D0%BD%D0%B8%D0%B5-%D0%B8-%D1%80%D0%B5%D0%BF%D0%BE%D0%B7%D0%B8%D1%82%D0%BE%D1%80%D0%B8%D0%B9/hw1.ipynb"
   ```
3. Положите нетронутый стартер в `main`, потом заведите ветку для работы:

```
git switch main
git add notebooks/hw1.ipynb
git commit -m "Добавить стартовый ноутбук ДЗ-1"
git push
git switch -c feature/hw1
```

Стартер лежит в `main`, работа — в ветке. Тогда во вкладке **Files changed** pull request будет видно ровно то, что написали вы, и я смогу оставить комментарий к конкретной строке.

### 5. Работа

Из корня `prime-monitor` запустите `uv run jupyter lab` и откройте `notebooks/hw1.ipynb`. **Работаете в VS Code** — File → Open Folder → папка `prime-monitor`, откройте `notebooks/hw1.ipynb`, справа сверху Select Kernel → Python Environments → `.venv` из `prime-monitor`; вместо Restart Kernel and Run All Cells — кнопки Restart и Run All над ноутбуком. JupyterLab запускается **именно из `prime-monitor`**, а не из клона репозитория курса: там нет пакета `prime` и вашего `.env`. Этот терминал останется занят, поэтому git-команды дальше вводите во втором окне терминала, тоже в папке `prime-monitor` (или **File → New → Terminal** в самом JupyterLab).

Дальше всё написано в самом ноутбуке. Он в четырёх частях:

| Часть | Что делаете |
|---|---|
| **1. Подготовка** | вписываете пять значений вашего участка и запускаете готовые ячейки |
| **2. Восемь задач** | пишете функции задач и ответы словами в ячейках «✍️ Ответ на вопрос N» |
| **3. Итог** | запускаете перед сдачей: ячейка покажет ваши ответы и проверит их формат |
| **4. Исследование** | по желанию — для тех, кто хочет 9 или 10 |

Ноутбук **не сообщает**, правильно ли вы посчитали, — только в нужном ли формате записан ответ. Правильность проверяю я.

Коммитьте по ходу работы, не одним куском в конце:

```
git add notebooks/hw1.ipynb
git commit -m "Решить задачи 1–3 и ответить на вопросы"
```

Заполните `README.md` (строка «Автор» и раздел «Что здесь»; раздел «Что здесь считается» пока не трогайте) и `ДЕКЛАРАЦИЯ-ИИ.md` и закоммитьте их в ту же ветку:

```
git add -u
git commit -m "Заполнить README и декларацию"
```

`git add -u` добавляет изменения во всех файлах, которые git уже отслеживает; `.env` он не тронет. Если README вы уже заполняли на семинаре — повторно ничего делать не нужно.

### 6. Pull request и сдача

```
git push -u origin feature/hw1
```

В ответ GitHub напечатает ссылку вида `https://github.com/…/pull/new/feature/hw1`. Откройте её, проверьте, что сверху написано `main` ← `feature/hw1` и репозиторий ваш, и нажмите **Create pull request**. **Merge не нажимайте.**

Скопируйте адрес открывшейся страницы — это и есть ссылка на pull request — и отправьте её боту командой `/submit`.

**После сдачи**

- **Проверяется версия на момент вашей последней отправки в `/submit`.** Хотите что-то исправить — `git push` в ту же ветку и **снова** `/submit`: учитывается последняя отправка, а бот предупредит, если она пришла после дедлайна. Push без повторной отправки не учитывается.
- Комментарии к работе я оставляю прямо в pull request — во вкладке **Files changed**.
- Когда в боте появилась оценка, нажмите **Merge pull request** и заберите слитое к себе: `git switch main`, затем `git pull`. Как вести ветку ДЗ-2, которое выдаётся раньше, чем придёт оценка за ДЗ-1, — будет сказано в тексте ДЗ-2.

## Как оценивается

**Основная часть — до 8 баллов. 9 и 10 — только за исследование.** Сделали всё аккуратно и с верными выводами — это 8, и это «отлично».

### Основная часть: 20 баллов, оценка = сумма × 0,4

| Блок | Проверка | Баллы |
|---|---|---|
| **1. Репозиторий и сдача** | открытый pull request `feature/hw1` → `main`, ссылка на него в `/submit` открывается | 1 |
| | в git нет `.env`, выгрузок данных и `.ipynb_checkpoints`; пароля нет ни в одном коммите; ноутбук закоммичен без выводов | 1 |
| | `README.md`: автор и раздел «Что здесь» своими словами | 1 |
| | `ДЕКЛАРАЦИЯ-ИИ.md` заполнена, раздел «Что я проверил сам» не пустой | 1 |
| **2. Воспроизводимость** | `uv sync --locked` проходит на вашей ветке | 1 |
| | подключение к базе только через `.env`: в коде и в ноутбуке нет логина и пароля | 1 |
| | ноутбук выполняется целиком без правок на вашем участке | 1 |
| | ноутбук выполняется целиком без правок на контрольном участке — включая ваши ячейки расчётов | 1 |
| **3. Код задач** | 8 задач по 0,5. Полные 0,5 — ответ верный и на вашем участке, и на контрольном. Верно по сути, но формат не тот — 0,25. Верно только на вашем участке — 0, и по коду этой задачи будет устный вопрос | 4 |
| **4. Ответы словами** | 8 ответов по 1 баллу: числа верные — 0,5; вывод из них верный и объяснён — ещё 0,5. Сомнительный вывод — без второй половины. Ответ без ваших чисел, противоречащий им или написанный LLM — 0 | 8 |

**Контрольный участок.** При проверке я запускаю ваш ноутбук ещё раз, подставив в ячейку 1.1 другой участок той же таблицы. Если код честно считает по `rows`, ответы пересчитаются сами. Если ответ вписан руками или код завязан на ваши даты и сегмент — не пересчитаются. Поэтому значения участка пишутся **только** в ячейке 1.1.

**Ответ словами на 1 балл** — это 2–4 предложения, в которых есть ваши числа и ваш вывод из них. Пример формы, не содержания — ситуация и числа выдуманы и к ПРАЙМ отношения не имеют: «Из 1 204 заказов пекарни не доставлено 37 — 3,1 %, на 9 870 ₽. Но часть клиентов могла перезаказать в тот же день, поэтому потерянная выручка, скорее всего, меньше этой суммы. Я бы проверил, сколько из этих 37 клиентов сделали новый заказ в течение суток».

### Исследование: до +2 балла

Часть 4 ноутбука — два открытых исследования, каждое до 1 балла сверху. **Засчитываются, если основная часть набрала не меньше 15 баллов из 20.**

| Каждое исследование | Балл |
|---|---|
| числа верные и получены кодом в ноутбуке, а не вписаны руками | 0,4 |
| вывод следует из чисел, названо, чего расчёт не доказывает | 0,3 |
| код исследования выполняется у меня целиком, в том числе на контрольном участке. Ошибка в коде исследования снимает только эти 0,2 и не трогает основную часть | 0,2 |
| изложено по схеме: вопрос → как проверяли → что получилось → что это значит | 0,1 |

**Итоговая оценка = сумма основной части × 0,4 + баллы за исследования**, не больше 10.

### Как это ложится на критерии программы

Критерии программы дисциплины сохраняют свои доли — 40 / 30 / 20 / 10 %. Таблица показывает, из чего складывается каждая доля; это раскладка суммы по критериям, а не отдельные правила начисления.

| Критерий программы | Основная часть, из 20 | Исследование, из 1 за каждое |
|---|---|---|
| корректность результата и отсутствие методических ошибок | 8: ответы задач — 3, числа в ответах словами — 4, гигиена git — 1 | 0,4 |
| обоснованность решений и качество кода | 6: код работает на контрольном участке — 1, выводы в ответах — 4, подключение через `.env` — 1 | 0,3 |
| воспроизводимость запуска у преподавателя | 4: pull request, `uv sync --locked`, прогон на вашем и на контрольном участке | 0,2 |
| оформление результата и декларация ИИ | 2: README и декларация | 0,1 |

**Неспособность объяснить собственный код или ответ обнуляет оценку за задание.** Вопросы будут не по теории, а по вашей работе: почему здесь так и что сломается, если убрать эту строку.

В `README.md` шаблона в комментарии написано, что README стоит «1 балл из 10». Это старая разбалловка, действует эта. Правила просрочки — общие для всех заданий, [здесь](../README.md#просрочка).

## Если что-то не работает

| Что видите | Что случилось и что делать |
|---|---|
| `Пакет prime не найден` | ноутбук запущен не в окружении `prime-monitor`. JupyterLab — закройте его, перейдите в корень `prime-monitor`, `uv run jupyter lab`. VS Code — Select Kernel → `.venv` из папки `prime-monitor` |
| `Не найдена переменная PRIME_DSN` | нет `.env` в корне `prime-monitor` или в нём нет строки `PRIME_DSN=` — [памятка](../../справка/подключение-к-базе.md) |
| подключение висит, `timed out` | сеть режет порт 5432 — замените в `.env` `:5432` на `:443` |
| `server closed the connection unexpectedly`, `terminating connection` | соединение оборвалось (сон ноутбука, смена сети) — запустите заново ячейки 1.2 и 1.5 |
| `NameError: name 'rows' is not defined` (или другое имя) | какая-то ячейка выше не выполнилась. Найдите сверху первую ячейку с красной ошибкой, исправьте её и сделайте **Restart Kernel and Run All Cells** |
| `❌ не решена` в итоге | функция вернула `None`: в ней остался `...` или забыт `return` |
| `❌ нужен …, сейчас …` в итоге | ответ записан не в том формате: сравните с «Форматом ответа» у задачи |
| `clean filter 'nbstripout' failed` при `git add` | папку проекта перенесли — `uv run nbstripout --install` |
| `pathspec 'notebooks/hw1.ipynb' did not match any files` | файл лёг не туда или называется иначе (`hw1 (1).ipynb`, `hw1.ipynb.txt`): посмотрите `ls notebooks` (в PowerShell — `dir notebooks`) и переименуйте |
| `Need to specify how to reconcile divergent branches` | `git pull --no-rebase`, затем снова `git push`. README и декларацию дальше правьте у себя, а не в браузере на GitHub |
| `unresolved conflict` или `cannot switch branch while merging` | остался недоделанный конфликт из Git-практикума: `git merge --abort` |
| `a branch named 'feature/hw1' already exists` | ветка уже есть — `git switch feature/hw1` |
| отправили ссылку вида `…/pull/new/feature/hw1` | это ещё не pull request: откройте её, нажмите **Create pull request** и отправьте в `/submit` адрес открывшейся страницы |
| репозиторий сделан кнопкой **Fork**, а не **Use this template** | fork нельзя сделать приватным, и pull request уйдёт в шаблон курса. Создайте на GitHub пустой репозиторий `prime-monitor` (без README и .gitignore), в папке проекта выполните `git remote set-url origin git@github.com:ВАШ_ЛОГИН_НА_GITHUB/prime-monitor.git` и `git push -u origin main`; fork после этого удалите |
| нажали **Merge** по ошибке | если работа уже готова — пришлите в `/submit` ссылку на этот pull request. Если продолжаете работу — пушьте в ту же ветку, откройте новый pull request `feature/hw1` → `main` и пришлите его ссылку |
| `git@github.com: Permission denied (publickey)` | GitHub вас не узнал — [памятка по git](../../справка/git-и-github.md), раздел «Если что-то пошло не так» |
| `port 22: Operation timed out` | сеть режет порт 22 — [памятка по git](../../справка/git-и-github.md), раздел 5 |
| `warning: VIRTUAL_ENV=… does not match the project environment` | безвредно: uv всё равно берёт окружение проекта. Чтобы не видеть — откройте новый терминал |
| `Kernel is running over TCP without encryption` | безвредно, не обращайте внимания |

Остальные ошибки git — в таблице в конце [Git-практикума](../../02-среда-git-python/семинар/С2-git-практикум.md).

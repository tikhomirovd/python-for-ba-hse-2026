# VS Code: редактор, терминал и Git «глазами»

Редактор в курсе не навязывается: если вам удобно в JupyterLab, PyCharm или Vim — работайте в них. Но по умолчанию мы предполагаем **VS Code**: он бесплатный, одинаковый на Windows и macOS, умеет и ноутбуки, и обычные модули, и внутри него есть терминал — не придётся переключаться между окнами.

К первому семинару он не обязателен. Начиная с темы 09, когда мы выйдем из ноутбуков в пакеты, он понадобится.

---

## Сразу про Git: чем мы будем пользоваться

VS Code умеет делать почти всё с Git мышкой. Но **в курсе мы работаем с Git из терминала**, и вот почему.

На лекции темы 02 разбираются команды: `git status`, `git diff`, `git add`, `git commit`, `git push`. На семинаре мы делаем то же самое руками. Если вы дома привыкнете нажимать кнопки, на семинаре придётся переучиваться на ходу — а когда что-то сломается, кнопка не покажет, что именно.

Ещё практическое: работу вы будете делать на своей машине, а объяснять — на защите, и вопросы будут про то, что произошло с репозиторием. Команды это объясняют, кнопки прячут.

**Поэтому правило простое:**

| Что | Чем |
|---|---|
| **Делать** — коммитить, ветвиться, пушить | терминал, командами |
| **Смотреть** — что изменилось, что застейджено, где конфликт | панель Source Control в VS Code |

Панель Git в VS Code — это хороший **монитор состояния**: она рисует то же самое, что печатает `git status`, только нагляднее, и показывает построчную разницу двумя колонками. Пользуйтесь ей как окном, а команды набирайте руками. Через месяц команды станут привычными, и это окупится.

Если совсем тяжело и Git не даётся — скажите об этом, не молчите. Отдельно разберём.

## 1. Установка

**Windows.** Скачайте с [code.visualstudio.com](https://code.visualstudio.com/), запустите установщик, оставьте предложенные галочки. Полезная — «Add to PATH», она стоит по умолчанию.

Либо одной командой:

```
winget install --id Microsoft.VisualStudioCode -e
```

**macOS.** Скачайте с [code.visualstudio.com](https://code.visualstudio.com/), распакуйте и перетащите **Visual Studio Code** в папку «Программы». Либо через Homebrew, если он у вас есть:

```
brew install --cask visual-studio-code
```

> **Git ставится отдельно.** VS Code не приносит Git с собой — он пользуется тем, что установлен в системе, и требует версию 2.0 или новее. Если вы ещё не ставили Git, начните с инструкции для [Windows](установка-windows.md) или [macOS](установка-macos.md), иначе панель Git будет пустой.

## 2. Русский интерфейс — если хочется

По умолчанию VS Code на английском. Можно переключить: `Ctrl+Shift+X` (macOS: `⇧⌘X`), в поиске набрать `Russian Language Pack`, установить **Russian Language Pack for Visual Studio Code** (издатель MS-CEINTL), перезапустить.

Решайте сами. Аргумент за английский: все инструкции, ответы на Stack Overflow и тексты ошибок — на нём, и искать проблему проще, когда пункт меню называется так же, как в найденном совете. Дальше в этом файле названия даны на английском, а русский перевод — в скобках.

## 3. Открыть проект

**File → Open Folder…** (Файл → Открыть папку) и выбрать **папку проекта целиком** — не отдельный файл.

Это важнее, чем кажется: VS Code берёт открытую папку за корень. От неё он ищет `.venv`, от неё же работает панель Git. Если открыть одиночный файл, не будет ни автодополнения по вашему коду, ни Git-панели.

На macOS удобно добавить команду `code`: `⇧⌘P` → набрать `Shell Command: Install 'code' command in PATH`. После этого из терминала работает `code .` — открыть текущую папку.

---

## 4. Встроенный терминал

Открыть и закрыть: **`Ctrl+` `** (клавиша с обратным апострофом, слева от единицы). На macOS — **`⌃` `**, именно Control, не Command.

Терминал открывается сразу в папке проекта — это ровно то, что нужно: `uv run …` и `git …` можно набирать, не переходя никуда.

**На Windows проверьте, какая оболочка запустилась.** В выпадающем списке справа от значка **+** в панели терминала перечислены найденные: PowerShell, Command Prompt, Git Bash, WSL. Нужна **PowerShell**. Если по умолчанию открылся Command Prompt, смените: `Ctrl+Shift+P` → `Terminal: Select Default Profile` → PowerShell, затем откройте новый терминал.

Несколько терминалов — значок **+**; переключение между ними — список вкладок справа.

## 5. Расширения

Ставятся так: `Ctrl+Shift+X` (macOS: `⇧⌘X`), поиск по названию, кнопка **Install**.

**Нужны для курса:**

| Расширение | Издатель | Зачем |
|---|---|---|
| **Python** | Microsoft | подсветка, автодополнение, запуск, отладка. Подтягивает Pylance и отладчик сам |
| **Jupyter** | Microsoft | ноутбуки `.ipynb` прямо в редакторе |

**Пригодятся, но не обязательны:**

| Расширение | Издатель | Зачем |
|---|---|---|
| **Rainbow CSV** | mechatroner | раскрашивает колонки CSV — глазами читать выгрузки становится реально |
| **Even Better TOML** | tamasfe | подсветка `pyproject.toml` |
| **Ruff** | Astral Software | показывает проблемы в коде на лету; пригодится к теме 11 |
| **GitLens** | GitKraken | показывает у каждой строки, кто и когда её менял, и историю файла |

GitLens и Git Graph — как раз тот случай, когда смотреть глазами полезно, а делать всё равно командами.

## 6. Подключить окружение проекта

Один раз на проект, иначе VS Code будет подсказывать не из того Python.

`Ctrl+Shift+P` (macOS: `⇧⌘P`) → `Python: Select Interpreter` → выбрать тот, в пути которого есть **`.venv`** вашего проекта. Обычно он уже стоит первым с пометкой `Recommended`.

Проверить, что попали: внизу справа в строке состояния появится версия — должна быть **3.12** или выше.

> Помните: `uv run` работает правильно и без всего этого. Выбор интерпретатора нужен только редактору — чтобы автодополнение и подсветка ошибок смотрели в то же окружение, где реально стоит pandas.

## 7. Ноутбуки

Откройте `.ipynb` — он покажется ячейками, как в Jupyter. Кнопка **Select Kernel** справа сверху → **Python Environments** → `.venv` вашего проекта.

Запуск ячейки — `Shift+Enter`. Полезное для курса: **Restart** и **Run All** рядом наверху — это и есть проверка «мой ноутбук воспроизводится», которую мы разбираем на теме 02 и требуем в проектах.

Если привычнее классический JupyterLab, он никуда не делся:

```
uv run jupyter lab
```

## 8. Панель Git: что вы там увидите

Открыть: значок с ветвлением на левой панели или **`Ctrl+Shift+G`** (macOS: **`⌃⇧G`**, Control, не Command).

Соответствие тому, что мы делаем в терминале:

| В терминале | В панели |
|---|---|
| `git status` | список **Changes** — все изменённые файлы |
| `git diff <файл>` | клик по файлу → две колонки: слева было, справа стало |
| `git add <файл>` | значок **+** у файла, он переезжает в **Staged Changes** |
| `git commit -m "…"` | поле сообщения сверху и кнопка **Commit** |
| `git push` | кнопка **Sync Changes** в строке состояния внизу |
| `git branch` | имя текущей ветки — внизу слева, клик переключает |

Самое ценное здесь — **вторая строка**: увидеть построчную разницу перед коммитом. В терминале `git diff` тоже это показывает, но двумя колонками читается быстрее, особенно когда правок много. Возьмите за привычку смотреть diff перед каждым коммитом — это ровно то, что отделяет осмысленный коммит от «сохранил всё подряд».

### Конфликт слияния

Единственное место, где кнопки честно удобнее командной строки.

Когда `git merge` или `git pull` упрётся в конфликт, конфликтные файлы подсветятся в панели. Откройте такой файл — VS Code нарисует прямо в тексте варианты с кнопками **Accept Current Change**, **Accept Incoming Change**, **Accept Both Changes**.

Только не жмите наугад. Прочитайте оба варианта и решите, какой код должен остаться, — кнопка тут экономит набор символов, а не мышление. Разбираем это на семинаре темы 02.

## 9. А если Git совсем не идёт?

Есть [GitHub Desktop](https://desktop.github.com/) — отдельная программа, где клонирование, коммит и пуш сделаны большими кнопками, и терминал не нужен вовсе.

В курсе мы им не пользуемся и на семинарах не показываем. Как временный костыль на первые недели — можно, если иначе вы застреваете и не двигаетесь дальше. Но к теме 09 стоит перейти на команды: дальше начнётся работа, где кнопок уже не будет.

## Если что-то пошло не так

**Панель Git пустая или пишет, что репозитория нет**

Скорее всего, открыт файл, а не папка: **File → Open Folder…** и выбрать корень проекта. Второй вариант — папка действительно ещё не репозиторий, тогда в терминале `git init`.

**«Git not found» при запуске**

VS Code не видит Git. Проверьте в терминале `git --version`; если команда не находится — вернитесь к установке Git для [Windows](установка-windows.md) или [macOS](установка-macos.md). Если находится, но VS Code всё равно жалуется — перезапустите VS Code целиком, он читает `PATH` при старте.

**Красные подчёркивания под `import pandas`, хотя код работает**

Не выбран интерпретатор — см. пункт 6. Признак тот же: подсказки при наборе не появляются.

**В терминале VS Code `uv` не находится, а в обычном терминале находится**

VS Code запустился раньше, чем установщик дописал `PATH`. Закройте VS Code полностью и откройте заново.

**Ноутбук не запускается, ядро не выбирается**

Не установлено расширение Jupyter (пункт 5) либо в окружении нет самого Jupyter. Второе лечится так:

```
uv add jupyter
```

Не получилось — не тратьте на это вечер. Возвращайтесь к разделу [«Если не получилось»](к-семинару.md#если-не-получилось): напишите в чат с текстом ошибки или приходите на семинар за 10–15 минут до начала.

# Установка окружения: macOS

Ставим две вещи: **Git** и **uv**. Python отдельно ставить не нужно — его поставит uv.

Права администратора не нужны ни на одном шаге. Всё ставится в вашу домашнюю папку.

Открыть терминал: **⌘ + пробел**, набрать «Терминал», Enter. Дальше все команды выполняются в нём: копируете строку, вставляете, Enter.

---

## 1. Git

Сначала проверьте — возможно, он уже есть:

```
git --version
```

Если напечаталось `git version 2.39.5` (номер может быть другим) — Git есть, переходите к шагу 2.

Если вместо этого выскочило окно «Для использования команды "git" требуются инструменты разработчика командной строки» — нажмите **«Установить»** и дождитесь конца. Это официальный компонент Apple, весит около 1 ГБ, ставится 5–10 минут.

Если окно не появилось, запустите установку вручную:

```
xcode-select --install
```

После установки закройте терминал, откройте заново и проверьте `git --version` ещё раз.

> Отдельно ставить Git с сайта git-scm.com или через Homebrew не нужно — версия от Apple полностью подходит для курса.

---

## 2. uv

```
curl -LsSf https://astral.sh/uv/install.sh | sh
```

Установщик скачает uv в `~/.local/bin` и сам пропишет эту папку в `PATH`.

**После установки закройте терминал и откройте новый.** Без этого команда `uv` не найдётся: переменная `PATH` перечитывается только при запуске оболочки.

Проверяем:

```
uv --version
```

Должно напечататься что-то вроде `uv 0.10.12`.

<details>
<summary>Если у вас уже стоит Homebrew</summary>

Можно поставить и через него — разницы для курса нет:

```
brew install uv
```

Обновляется тогда тоже через Homebrew (`brew upgrade uv`), а не через `uv self update`.
</details>

## 3. Представьтесь Git

Git подписывает каждый коммит именем и почтой. Пока они не заданы, первый же коммит упадёт с ошибкой — сделайте это сразу:

```
git config --global user.name "Иван Иванов"
git config --global user.email "iivanov@edu.hse.ru"
```

Почту укажите ту же, что и в аккаунте GitHub, — тогда коммиты будут привязываться к вашему профилю.

## 4. Проверка

```
uv init --python 3.12 proba
cd proba
uv add pandas
uv run python -c "import sys, pandas; print(sys.version); print(pandas.__version__)"
```

Ожидаемый результат:

```
3.12.13 (main, ...)
3.0.5
```

Python должен быть **3.12** или выше, pandas — **3.x**. Если так — всё готово, папку `proba` можно удалить:

```
cd ..
rm -rf proba
```

## У меня уже есть Python

Ничего не сломается, и делать ничего не нужно.

На типичном ноутбуке аналитика к третьему курсу скапливается несколько Python сразу: системный в `/usr/bin/python3`, из Homebrew, из pyenv, из установщика с python.org, из Anaconda. Это нормально и это не проблема.

uv **не трогает ни один из них**. Он не меняет `PATH`, не переставляет символические ссылки, не переключает «активную» версию. Он делает одно из двух:

- находит на машине подходящий Python 3.12 и использует его **только на чтение**;
- если подходящего нет — скачивает свой собственный в `~/.local/share/uv/python/`, отдельно от всего остального.

Проверить, что именно uv видит на вашей машине:

```
uv python list
```

В выводе будут все найденные интерпретаторы и те, что доступны для скачивания. Например:

```
cpython-3.12.13-macos-aarch64-none    <download available>
cpython-3.12.9-macos-aarch64-none     /opt/homebrew/bin/python3.12
cpython-3.12.0-macos-aarch64-none     /Users/ivanov/.pyenv/shims/python3.12
cpython-3.10.11-macos-aarch64-none    /usr/local/bin/python3
cpython-3.9.6-macos-aarch64-none      /usr/bin/python3
```

Хотите, чтобы uv гарантированно взял свой Python и вообще не смотрел на установленные, — добавьте флаг:

```
uv add --managed-python pandas
```

**Почему проекты не мешают друг другу.** Каждый проект держит своё окружение в папке `.venv` внутри себя, а нужную версию Python — в файле `.python-version` рядом. Наш курс требует Python 3.12 и pandas 3; ваш прошлогодний проект на Python 3.10 и pandas 2 продолжит работать на своих версиях. Они физически лежат в разных папках и не пересекаются.

**Anaconda.** Оставляйте как есть. Единственное, что стоит знать: если в приглашении терминала висит `(base)`, это активное окружение conda. На uv оно не влияет, но если хочется убрать его из автозапуска:

```
conda config --set auto_activate_base false
```

**Про `activate`.** В этом курсе он не понадобится ни разу. Команда `uv run` сама находит окружение по текущей папке и запускает код в нём. Если вы привыкли к `source .venv/bin/activate` — можно и так, но это лишний шаг.

## Если что-то пошло не так

**`zsh: command not found: uv`**

Почти всегда — не перезапущен терминал. Закройте окно терминала целиком (⌘Q) и откройте заново.

Если не помогло, проверьте, что файл на месте:

```
ls ~/.local/bin/uv
```

Если файл есть, а команда не находится — допишите путь вручную:

```
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.zshrc
source ~/.zshrc
```

**`curl: (7) Failed to connect` или установщик молча ничего не делает**

Сеть блокирует загрузку. Попробуйте с мобильного интернета или из дома. Если не выходит — поставьте через Homebrew (`brew install uv`) или напишите в чат курса, дадим файл напрямую.

**`uv add pandas` долго висит и падает по таймауту**

Не проходит доступ к PyPI — это бывает на корпоративных сетях и под некоторыми VPN. Выключите VPN и попробуйте снова. Если у вас корпоративный ноутбук с прокси — напишите в чат, разберёмся отдельно.

**Xcode Command Line Tools не ставятся, ошибка «Не удалось установить ПО»**

Обычно лечится так:

```
sudo rm -rf /Library/Developer/CommandLineTools
xcode-select --install
```

Либо скачайте Command Line Tools вручную с [developer.apple.com/download/all](https://developer.apple.com/download/all/) — нужен бесплатный Apple ID.

**У меня старый Mac на процессоре Intel**

Всё работает одинаково, uv сам определит архитектуру. Специально ничего делать не нужно.

**macOS младше 12 (Monterey)**

Напишите в чат курса до семинара — посмотрим на месте, возможно, понадобится более старая сборка Python.

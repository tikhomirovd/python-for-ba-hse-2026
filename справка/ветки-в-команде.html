Git втроём

Как разделить дневной отчёт на задачи, работать параллельно и собрать проверенные изменения в одной ветке main.

Аня считает выручку

Из трёх платежей на 100, 200 и 50 ₽ прошли первые два. Значит, в выручке должно быть 300 ₽.

Борис считает отказы

Один платёж из трёх отклонён. Доля отказов за день равна ⅓. Борис проверяет её на тех же данных.

Вера собирает сводку

Пока коллеги пишут код, Вера передаёт в шаблон 300 и ⅓. В готовом отчёте должны появиться «300 ₽» и «33,3 %».

Распределение задач

Одна ветка или две?

Держите в main проверенную версию проекта. Если все трое пишут разные фичи в одной ветке, готовая выручка может застрять из-за незаконченной сводки. Что можно проверить и влить отдельно?

Я написала две функции для выручки. Коллега добавляет третью — отбор по дате только для этой метрики. Сколько веток взять?

Как бы вы организовали работу?

От ветки до pull request

Как влить изменения в main

Пройдём путь Ани. Команды выполняйте в терминале из корня своего клона командного репозитория.

01Начните задачу от свежей main

Договоритесь, что войдёт в эту фичу. У Ани это расчёт дневной выручки и его тест. Проверьте, что рабочая копия чистая, обновите main и создайте ветку.

git status
git switch main
git pull --ff-only
git switch -c feature/revenue
02Проверьте расчёт и отправьте ветку

Добавьте реализацию и тест на три платежа. Ниже пример для проекта с pytest. Подставьте пути своих файлов. После теста запишите изменения в коммит и отправьте его на GitHub.

uv run pytest tests/test_revenue.py
git add src/prime/revenue.py tests/test_revenue.py
git commit -m "Рассчитать выручку по успешным платежам"
git push -u origin feature/revenue

В тесте выручка должна быть 300 ₽. Если получилось 350 ₽, в сумму попал отклонённый платёж.

03Откройте PR и попросите коллегу проверить

На GitHub откройте Pull requests → New pull request. Выберите base = main (куда вливаем) и compare = feature/revenue (откуда). Нажмите Create pull request.

В описании укажите, что изменилось и как это проверить. Например, «Два успешных платежа на 100 и 200 ₽ и один отказ на 50 ₽ дают выручку 300 ₽. Проверка — uv run pytest tests/test_revenue.py».

Борис открывает Files changed и смотрит, проверяет ли тест исключение отказов. Если понадобятся правки, Аня делает новый коммит в этой же ветке и выполняет git push. Изменения появятся в открытом PR.

04Проверьте совместимость и выполните merge

Когда коллега проверил изменения, замечания учтены и тесты проходят, нажмите в PR Merge pull request → Confirm merge. На схеме выбран вариант Create a merge commit. Кружок на main показывает, где сошлись две истории.

Если PR зависит от чужого кода, сначала влейте зависимость. Так делает Вера после слияния обеих метрик. С сохранёнными в коммите правками она обновляет свою ветку, подключает реальные расчёты и проверяет сводку целиком.

git switch feature/summary
git fetch origin
git merge origin/main

После подключения расчётов добавьте изменённые файлы через git add, сделайте коммит, запустите тесты и выполните git push. Коллега проверяет итоговый PR Веры перед слиянием.

Что делать, если Git показал конфликт?

Оставайтесь в ветке задачи. Команда git status покажет спорные файлы. Откройте их и найдите блоки между <<<<<<<, ======= и >>>>>>>. Вместе с автором второй правки соберите нужную версию и удалите маркеры.

Например, если вы оба добавили показатель в одну строку сводки, проверьте, что в ней видны и выручка, и доля отказов. Для конфликта в src/prime/summary.py команды будут такими.

git add src/prime/summary.py
uv run pytest
git commit -m "Объединить изменения сводки"
git push
05Обновите main у себя

После слияния на GitHub каждый у себя переключается на main и забирает изменения. В примере после последнего PR команда запускает тест сводки на трёх платежах и видит оба показателя. Следующую фичу начинайте от обновлённой main.

git switch main
git pull --ff-only
uv run pytest

Итоговый проект проверяется по main на момент отправки. Перед сдачей убедитесь, что нужные PR влиты, и каждый участник отправил ссылку на общий репозиторий через /submit.

# Установка окружения: Windows

Ставим две вещи: **Git** и **uv**. Python отдельно ставить не нужно — его поставит uv.

Права администратора не нужны: и Git, и uv умеют ставиться только для вашего пользователя.

## В каком терминале работать

**PowerShell.** Нажмите **Win**, наберите `PowerShell`, откройте «Windows PowerShell» (на Windows 11 — приложение «Терминал»).

Не используйте старую командную строку `cmd.exe` — часть команд в ней ведёт себя иначе.

> Git for Windows поставит ещё и **Git Bash**. Он тоже пригодится — в нём работают команды из инструкций для macOS и Linux, которых в интернете большинство. Но всё, что нужно для курса, делается в PowerShell.

## 1. Git

Проверьте, вдруг уже стоит:

```
git --version
```

Если напечаталась версия — переходите к шагу 2. Если «не является внутренней или внешней командой» — ставим.

**Способ 1, установщик.** Скачайте с [git-scm.com/download/win](https://git-scm.com/download/win) и запустите. Установщик задаёт много вопросов — **на всех экранах оставляйте предложенные значения** и жмите Next. Они разумные.

Один экран стоит прочитать: **«Adjusting your PATH environment»**. Должен быть выбран средний вариант — *Git from the command line and also from 3rd-party software*. Он и стоит по умолчанию.

**Способ 2, одной командой.** Если у вас Windows 10 версии 1809 или новее:

```
winget install --id Git.Git -e --source winget
```

После установки **закройте PowerShell и откройте новый** — иначе `git` не найдётся.

---

## 2. uv

```
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

Скопируйте строку целиком, вместе с `powershell -ExecutionPolicy ByPass -c`. Эта часть нужна: без неё Windows по умолчанию запрещает выполнять скачанные скрипты.

**После установки закройте PowerShell и откройте новый.**

Проверяем:

```
uv --version
```

Должно напечататься что-то вроде `uv 0.10.12`.

<details>
<summary>Альтернатива — через winget</summary>

```
winget install --id=astral-sh.uv -e
```

Обновляется тогда через `winget upgrade astral-sh.uv`, а не через `uv self update`.
</details>

## 3. Представьтесь Git

Git подписывает каждый коммит именем и почтой. Пока они не заданы, первый же коммит упадёт с ошибкой:

```
git config --global user.name "Иван Иванов"
git config --global user.email "iivanov@edu.hse.ru"
```

Почту укажите ту же, что и в аккаунте GitHub.

## 4. Куда класть проекты

Важнее, чем кажется. Заведите себе папку с **коротким путём и латинским именем**:

```
mkdir C:\work
cd C:\work
```

Причина: у многих домашняя папка называется по-русски — `C:\Users\Иван Иванов\`. Пробел и кириллица в пути ломают часть инструментов Python-экосистемы, причём с невнятными ошибками, на которые уходит вечер. `C:\work` снимает вопрос заранее.

Заодно это спасает от ограничения Windows на длину пути в 260 символов: глубокая вложенность вроде `Рабочий стол\Учёба\1 курс\Python\...` его выбирает быстро.

## 5. Проверка

```
cd C:\work
uv init --python 3.12 proba
cd proba
uv add pandas
uv run python -c "import sys, pandas; print(sys.version); print(pandas.__version__)"
```

Ожидаемый результат:

```
3.12.13 (main, ...)
3.0.5
```

Python должен быть **3.12** или выше, pandas — **3.x**. Если так — всё готово. Папку можно удалить:

```
cd C:\work
Remove-Item -Recurse -Force proba
```

## У меня уже есть Python

Ничего не сломается, и делать ничего не нужно.

uv **не трогает** установленные у вас Python: не меняет `PATH`, не переключает «активную» версию, не переустанавливает пакеты. Он делает одно из двух:

- находит подходящий Python 3.12 и использует его **только на чтение**;
- если такого нет — скачивает свой в `%LOCALAPPDATA%\uv\data\python\`, отдельно от всего остального.

Посмотреть, что uv видит на вашей машине:

```
uv python list
```

Заставить его взять свой Python и не смотреть на установленные:

```
uv add --managed-python pandas
```

**Почему проекты не мешают друг другу.** Каждый проект держит окружение в папке `.venv` внутри себя, а нужную версию Python — в файле `.python-version` рядом. У нашего курса свой Python 3.12 и pandas 3, у вашего старого проекта — свои. Они лежат в разных папках и друг о друге не знают.

**Anaconda.** Оставляйте как есть, uv с ней не конфликтует. Если в приглашении висит `(base)` — это активное окружение conda; на работу uv оно не влияет. Убрать из автозапуска, если мешает:

```
conda config --set auto_activate_base false
```

**Python из Microsoft Store и «заглушка».** Если вы наберёте `python` и откроется Microsoft Store — это встроенная в Windows заглушка, а не Python. Отключать её не нужно: uv её игнорирует, а мы всё равно запускаем код через `uv run`, а не через `python`.

**Про `activate`.** В курсе он не понадобится: `uv run` сам находит нужное окружение по текущей папке.

## Если что-то пошло не так

**`uv : Имя "uv" не распознано как имя командлета`**

Почти всегда — не перезапущен PowerShell. Закройте окно и откройте новое.

Если не помогло, проверьте, что файл на месте:

```
Test-Path "$env:USERPROFILE\.local\bin\uv.exe"
```

Если `True`, а команда не находится — допишите путь вручную:

```
$env:Path = "$env:USERPROFILE\.local\bin;$env:Path"
```

Это чинит только текущее окно. Чтобы навсегда: **Win** → «Изменение переменных среды текущего пользователя» → `Path` → «Создать» → вставить `%USERPROFILE%\.local\bin` → ОК, затем перезапустить PowerShell.

**`Выполнение сценариев отключено в этой системе`**

Вы запустили команду установки без префикса `powershell -ExecutionPolicy ByPass -c`. Скопируйте строку из шага 2 целиком.

**Антивирус удалил uv.exe или заблокировал установку**

Бывает с Kaspersky и корпоративными антивирусами: файл новый и неизвестный. Добавьте `%USERPROFILE%\.local\bin` в исключения либо поставьте через `winget`. Если ноутбук корпоративный и политика не даёт — напишите в чат курса.

**`uv add pandas` висит и падает по таймауту**

Не проходит доступ к PyPI. Чаще всего виноват VPN или корпоративный прокси — выключите VPN и попробуйте снова.

**Ошибки с путями, «file not found», кракозябры в выводе**

Скорее всего, проект лежит по пути с кириллицей или пробелами. Перенесите в `C:\work` (см. шаг 4) и повторите.

**Git ругается на `LF will be replaced by CRLF`**

Это предупреждение, а не ошибка, — Windows и macOS по-разному обозначают конец строки, и Git приводит их к общему виду. Игнорируйте. Если хотите, чтобы не писал:

```
git config --global core.autocrlf true
```

**`winget` не найден**

Он есть не во всех сборках Windows 10. Пользуйтесь установщиками: Git — с git-scm.com, uv — командой из шага 2.

# Семинар 2. Git-практикум

Всё, что здесь написано, делается **в терминале**, а не в ноутбуке. Ноутбук со второй половиной пары лежит рядом: [С2-идиомы.ipynb](С2-идиомы.ipynb).

За эту пару вы заводите репозиторий, в котором будете жить до декабря. В нём же сдаётся ДЗ-1 и собирается итоговый проект.

Нужен настроенный SSH-ключ — его делали на первой паре сегодня. Если не успели, вернитесь к памятке [«Git и GitHub»](../../справка/git-и-github.md), это пять минут.

---

## 1. Свой репозиторий из шаблона

Открываете шаблон проекта — **[github.com/tikhomirovd/prime-monitor-template](https://github.com/tikhomirovd/prime-monitor-template)** — и нажимаете зелёную кнопку **Use this template** → **Create a new repository**.

| Поле | Что поставить |
|---|---|
| Repository name | `prime-monitor` |
| Description | можно оставить пустым |
| Видимость | **Private** |

> **Почему Private.** Дальше в репозитории появятся ваши расчёты и ваш персональный срез данных. Публичный репозиторий — это приглашение списать у вас, а совпадение решений трактуется как нарушение академических норм для обеих сторон.

Готово: у вас свой репозиторий со всей структурой внутри.

## 3. Забрать репозиторий к себе

Кнопка **Code** → вкладка **SSH** → скопировать адрес. Он начинается с `git@github.com:`, а не с `https://`.

```
git clone git@github.com:ВАШ_ЛОГИН/prime-monitor.git
cd prime-monitor
uv sync
```

`uv sync` читает `uv.lock` и ставит **ровно те версии**, которые записаны в нём. Не «свежие на сегодня», а те же, что у всех остальных. Это и есть воспроизводимость, за которую в ДЗ-1 стоит 1,5 балла.

Проверка, что проект собрался:

```
uv run python -c "from prime.metrics import revenue; print(revenue([{'amount': 199.0}, {'amount': 399.0}]))"
```

Должно напечататься `598.0`.

## 4. Первый коммит

Положите доступ к базе на место — файл `.env` из вчерашней памятки:

```
cp .env.example .env
```

и впишите в `.env` строку, которую выдал бот по команде `/db`.

Теперь посмотрите, что видит git:

```
git status
```

**`.env` в списке не появился.** Он закрыт в `.gitignore` — так и задумано, и именно поэтому пароль не уедет на GitHub. Проверьте это глазами прямо сейчас: это тот случай, когда «работает» и «я убедился, что работает» — разные состояния.

Заполните в `README.md` строку с фамилией и раздел «Что здесь», после чего:

```
git add README.md
git commit -m "Заполнить README: автор и назначение проекта"
git push
```

## 5. Ветка и pull request

Работа никогда не делается прямо в `main`. Заводим ветку под задачу:

```
git switch -c feature/weekly-metrics
```

Откройте `src/prime/metrics.py` и допишите вторую функцию:

```python
def payments_count(payments: list[dict]) -> int:
    """Сколько было списаний."""
    return len(payments)
```

Дальше — шесть команд ежедневного цикла, вы их видели на лекции:

```
git status
git add src/prime/metrics.py
git commit -m "Добавить счётчик списаний"
git push -u origin feature/weekly-metrics
```

В ответ на `push` GitHub напечатает ссылку вида `https://github.com/…/pull/new/feature/weekly-metrics`. Откройте её — это и есть создание **pull request**.

На странице PR посмотрите вкладку **Files changed**: это тот самый `diff` со слайда, только нарисованный. Зелёное — что стало, красное — что было.

Нажмите **Create pull request**, затем **Merge pull request** и **Confirm merge**.

Заберите слитое к себе:

```
git switch main
git pull
```

> **Зачем всё это, если репозиторий ваш и рецензировать некому.** Затем, что ДЗ-1 сдаётся ссылкой на репозиторий с оформленным pull request, а в итоговом проекте вас будет двое или трое, и там это единственный способ не затирать работу друг друга. Форма отрабатывается сейчас, пока цена ошибки нулевая.

## 6. Конфликт: устраиваем намеренно

Конфликт возникает, когда **одну и ту же строку** поменяли в двух местах. Сейчас мы это подстроим.

### Ветка, которая фильтрует статусы

```
git switch -c feature/paid-only
```

В `src/prime/metrics.py` замените тело `revenue` на строку с фильтром:

```python
    return sum(p["amount"] for p in payments if p["status"] == "success")
```

```
git commit -am "Считать выручку только по успешным списаниям"
```

### Та же строка, но в main

```
git switch main
```

Снова откройте `src/prime/metrics.py` — он вернулся в исходное состояние, потому что вы на другой ветке. Замените ту же строку, но иначе:

```python
    return round(sum(p["amount"] for p in payments), 2)
```

```
git commit -am "Округлять выручку до копеек: расходились с бухгалтерией"
```

### Сталкиваем

```
git merge feature/paid-only
```

```
Auto-merging src/prime/metrics.py
CONFLICT (content): Merge conflict in src/prime/metrics.py
Automatic merge failed; fix conflicts and then commit the result.
```

**Это не авария.** Git увидел две несовместимые правки одной строки и отказался решать за вас — потому что решить может только человек, знающий, чего он хотел.

Откройте файл:

```python
def revenue(payments: list[dict]) -> float:
    """Выручка: сумма списаний."""
<<<<<<< HEAD
    return round(sum(p["amount"] for p in payments), 2)
=======
    return sum(p["amount"] for p in payments if p["status"] == "success")
>>>>>>> feature/paid-only
```

Между `<<<<<<< HEAD` и `=======` — то, что было у вас на `main`. Между `=======` и `>>>>>>>` — то, что пришло из ветки.

Не забудьте спросить `git status`, если растерялись:

```
On branch main
You have unmerged paths.
  (fix conflicts and run "git commit")
  (use "git merge --abort" to abort the merge)

Unmerged paths:
  (use "git add <file>..." to mark resolution)
	both modified:   src/prime/metrics.py
```

Git снова сам называет команды в скобках — и `git merge --abort` в их числе: если запутались совсем, эта команда откатит слияние целиком, как будто его не было.

### Решаем

Правильный ответ здесь — **обе половины сразу**: считать надо только успешные и округлять до копеек. Удалите три строки-маркера и оставьте одну строку:

```python
    return round(sum(p["amount"] for p in payments if p["status"] == "success"), 2)
```

Маркеров `<<<<<<<`, `=======`, `>>>>>>>` в файле остаться не должно ни одного.

```
git add src/prime/metrics.py
git commit -m "Слить feature/paid-only: только успешные списания, с округлением"
git push
```

Посмотрите, что получилось:

```
git log --oneline --graph
```

```
*   38878ac Слить feature/paid-only: только успешные списания, с округлением
|\
| * 9fd0a38 Считать выручку только по успешным списаниям
* | 72cd25e Округлять выручку до копеек: расходились с бухгалтерией
|/
* 0f7e54e Первый коммит: шаблон проекта
```

Развилка и схождение — вот как выглядит слияние изнутри.

## 7. Чтобы ноутбуки не раздували репозиторий

Файл `.ipynb` — это JSON, и выводы ячеек лежат прямо в нём: таблицы текстом, картинки в base64. Ноутбук на тридцать мегабайт — обычное дело, а `diff` по нему нечитаем.

Включается один раз на проект:

```
uv run nbstripout --install
```

Теперь при каждом коммите выводы срезаются **на лету**: в репозиторий уходит чистый код, а у вас на экране всё остаётся как было. Проверить можно так — закоммитьте любой ноутбук с выводами и посмотрите, что реально попало в историю:

```
git show HEAD:notebooks/ваш-ноутбук.ipynb | grep -c '"output_type"'
```

Ответ `0` — фильтр работает.

> **Если перенесёте папку проекта в другое место, фильтр сломается молча.** Он запоминает полный путь к `.venv`. Лечится повторным `uv run nbstripout --install`.

## 8. Если что-то пошло не так

| Что написано | Что случилось |
|---|---|
| `git@github.com: Permission denied (publickey)` | GitHub вас не узнал. Ключ не добавлен или скопирован не целиком — [памятка, раздел «Если что-то пошло не так»](../../справка/git-и-github.md) |
| `ssh: connect to host github.com port 22: Operation timed out` | сеть режет 22-й порт. Лечится файлом `~/.ssh/config` — [раздел 5 памятки](../../справка/git-и-github.md). Та же история, что с портом базы |
| `Username for 'https://github.com'` | репозиторий подключён по HTTPS. `git remote set-url origin git@github.com:ВАШ_ЛОГИН/prime-monitor.git` |
| `Updates were rejected because the remote contains work…` | на GitHub есть коммиты, которых нет у вас. `git pull`, потом снова `git push` |
| `error: Your local changes would be overwritten by merge` | есть незакоммиченные правки. Либо `git commit`, либо `git switch -c черновик` и коммит туда |
| `fatal: not a git repository` | вы не в папке проекта. `cd prime-monitor` |
| `Please tell me who you are` | git не знает вашего имени. `git config --global user.name` и `user.email` — [инструкции по установке](../../справка/) |

Не сидите над ошибкой в одиночку дольше пяти минут: скорее всего, то же самое сейчас у соседа.

## Что унести

* Работа идёт в ветке, а не в `main`.
* Не понимаете, что происходит, — `git status`. Он сам называет нужную команду.
* Конфликт — это отказ git решать за вас, а не поломка.
* `git merge --abort` возвращает всё как было.
* Пароль живёт в `.env`, `.env` — в `.gitignore`.
* Ноутбуки коммитятся без выводов.

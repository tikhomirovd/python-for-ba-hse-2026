## На лекции

- Зачем бизнесу пилот и почему «до и после» не работает даже в хорошем пилоте
- Потенциальные исходы и контрольная группа; А/Б-тест и сценарий с мэтчингом — два дизайна
- Формулировка гипотезы: от «нам кажется» к проверяемому утверждению; решающее правило до запуска
- Экспериментальная единица — клиент, подписка, устройство, регион. Шеринг подписки и «заражение» групп; что бывает, если делить клиентов, а считать покупки
- Основная и вспомогательные метрики, метрики-стражи
- Рандомизация и стратификация, АА-тест как проверка процедуры по обеим ошибкам — в HypEx
- Объём выборки и MDE, снижение дисперсии на этапе дизайна, длительность пилота
- Ограничения экспериментов в финансовых продуктах и источники смещения; дизайн-документ

Статистическая теория проверки гипотез здесь не дублируется — её читает НИС «Методы анализа данных». Мы занимаемся прикладной стороной: как поставить пилот и посчитать результат средствами Python.

## На семинаре

- Практикум: дизайн пилота «Кэшбэк 5 % на доставку» на данных ПРАЙМ — гипотеза и метрики, объём выборки, стратифицированное разбиение на три группы в HypEx, проверка ошибок I и II рода симуляцией, дизайн-документ

## Подготовка к семинару: окружение с HypEx

Темы 07–08 и ДЗ-3 работают на **HypEx 1.0.7**. Ему нужны pandas 2.2 и numpy 1.26, а в `prime-monitor` стоит pandas 3 — поэтому для пилотов отдельное окружение рядом с основным. **Поставьте его до пары**: первая загрузка пакетов идёт несколько минут.

1. Скачайте папку [`семинар/pilot/`](семинар/pilot/) — `pyproject.toml`, `uv.lock`, `.python-version` и скрипты установки — и положите её в **корень** своего `prime-monitor`, рядом с `src/` и `notebooks/`.
2. Из корня `prime-monitor`:

   ```
   uv sync --project pilot
   uv run --project pilot python -c "import hypex, pandas; print(hypex.__version__, pandas.__version__)"
   ```

   Должно напечатать `1.0.7 2.2.3`.

   То же одним скриптом — он сам проверит uv, поставит окружение и сверит версии:

   ```
   bash pilot/setup-pilot.sh                                        # macOS / Linux
   powershell -ExecutionPolicy Bypass -File pilot\setup-pilot.ps1   # Windows
   ```
3. Закоммитьте папку `pilot/` в `main` — без `.venv`, его уже закрывает `.gitignore`:

   ```
   git add pilot/pyproject.toml pilot/uv.lock pilot/.python-version pilot/setup-pilot.sh pilot/setup-pilot.ps1 && git commit -m "окружение для пилотов"
   ```

Запуск JupyterLab на темах 07–08 — **только так**, из корня `prime-monitor`:

```
uv run --project pilot jupyter lab
```

В VS Code: Select Kernel → `pilot/.venv`.

Пакет `prime` в этом окружении не устанавливается — первая ячейка ноутбука сама подключает ваш `src/`. Поэтому `from prime.config import get_engine` работает, как обычно, а `.env` берётся тот же.

| Что видите | Что случилось |
|---|---|
| `Нужен HypEx 1.0.7, а запущен …` или `No module named 'hypex'` | JupyterLab запущен из основного окружения: закройте его и запустите `uv run --project pilot jupyter lab` |
| `Не нашёл src/prime` | JupyterLab запущен не из корня `prime-monitor` |
| `НЕТ src/prime рядом с pilot/` (скрипт установки) | папка `pilot/` лежит не в корне `prime-monitor` — переложите её туда |
| `Нет .env с PRIME_DSN` (скрипт установки) | строку подключения выдаёт бот курса по команде `/db`; положите её в `.env` в корне `prime-monitor` |
| `KeyError: 'PRIME_DSN'` (в ноутбуке) | нет `.env` в корне `prime-monitor` или в нём нет строки `PRIME_DSN=…` — та же строка от бота `/db` |
| `No solution found when resolving dependencies` | старая версия uv — `uv self update` |
